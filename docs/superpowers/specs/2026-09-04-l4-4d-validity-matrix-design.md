# L4 四维有效性矩阵设计

## 目标

将 L4 评价从“整列因子必须在所有事件有效”改为按底层评价单元独立判定：

```text
factor × event × universe × label × split
```

其中 `split` 仅允许 `training` 和 `observation`。2025 留出区间在 L4 阶段不可读取、不可评价、不可参与阈值或候选决策。

## 单元状态契约

每个单元必须有且只能有一个状态：

- `pass`：因子值、横截面有效性、评价指标和日期覆盖均满足门槛；
- `not_ready`：生产端显式 readiness mask 表明因子在该事件尚未准备好；
- `metric_undefined`：因子值存在，但有效排名数、唯一值数或横截面标准差不足，无法定义 IC/RankIC；
- `coverage_fail`：理论上可计算，但有效日期覆盖率低于 95%；
- `data_error`：文件、日期、事件、键、因子列或有限值违反契约；
- `review`：数据合规，但方向稳定性、冗余或局部适用性需要人工审阅。

`not_ready` 不得由数值 0 推断；`metric_undefined` 不得伪装成 `not_ready`；任何 `data_error` 都是硬停止。未准备好或指标未定义的单元保留原因和计数，不填零、不删除事件。

## 单元检查字段

每个单元记录：日期数、有效因子值数、有效横截面数、有效覆盖率、横截面标准差、唯一值数、有效排名数、RankIC、IC、D1–D10、Long-Short、单调性、readiness 状态、状态原因和数据来源哈希。

`pass` 单元的日期覆盖率至少为 0.95；横截面检查使用冻结的事件级门槛。事件集合仍必须完整存在，不能因为某个因子不适用而删除事件。

## 汇总规则

- 事件级画像：展示完整 4D 单元矩阵；
- 股票池级、标签级和 split 级画像：只聚合 `pass` 单元；
- `not_ready` 和 `metric_undefined` 不参与均值、IR 或分组收益计算，也不转换成零；
- 因子级“可形成正式画像”的建议门槛为至少 6/8 个事件在大多数组合中通过，并且训练和观察均有有效证据；
- 训练有效但观察全部失效标记为 `observation_failure`；仅一个事件或一个股票池有效标记为 `insufficient_scope`；这些状态只进入人工审阅，不自动淘汰。

## 决策和留出隔离

L4 仅允许输出 `observation_only`，`promotion_allowed=false`。单个事件、股票池、标签或 split 的失败不得自动淘汰整个因子。留出区间路径不传入评价器，留出因子值、标签和收益指标均不得读取。

## 兼容性与迁移

旧的 12 份 Parquet 结果继续作为原始证据保存。评价验收器新增单元级有效性报告；如果旧结果缺少 readiness 列，只能将无法证明准备状态的单元标记为 `metric_undefined` 或 `review`，不得推断为 `not_ready`。现有 v1 画像和 L4 promotion gate 行为保持兼容。

## 验收标准

1. 测试覆盖所有六种单元状态、零值与未准备状态区分、按事件/股票池/标签/split 独立聚合以及 holdout 拒绝；
2. 当前 48 因子评价可以生成单元级报告，但不绕过数据错误和留出隔离；
3. 画像生成只消费通过契约的单元并保留完整失败原因；
4. 全部 campaigns、evaluations 和 C++ 测试通过，`git diff --check` 通过。
